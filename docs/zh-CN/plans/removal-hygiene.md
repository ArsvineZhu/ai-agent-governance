# 删除即删净（TASK 计划）

**Target：both** —— 本仓库侧 `AGENTS.md`；载荷侧 `SKILL.md`。同一规范两处落地，清单见「受影响文件」。

### 任务目的

确立文档变更规范——删除或替换内容时，正文只保留改后的正确表述；删除的原因记入历史记录层（CHANGELOG 或 ADR）。当前规范层（规则与文档正文）只陈述应做之事。

### 当前问题

- 删除某内容后，正文又追加否定式注脚（"不再展示""已删除""我们不这么做"），把删除动作本身写进了当前规范。
- 本次会话实例：diff 已从确认流程移除，计划正文却写"完整 diff 不默认展示"，经指出后清除。
- 注脚的危害：重新提及本不该出现的词；误导后续 Agent 以为该内容仍与流程相关；否定式禁令点出被删内容的名字，反而引好奇。

### 提议方案

- 正文只写应做之事：删除一个概念，正文不出现它的名称，也不出现"这里曾有过别的"的任何痕迹。
- 正文自足：改后的文本让未见过旧版的人读不出删除的痕迹。
- 历史归位：删除的原因记入 CHANGELOG 或 ADR。
- 判定标准：用被删内容的名称全仓搜索，正文命中数应为零；命中即未删净。

### 受影响文件

- `AGENTS.md` —— Conventions 增加一条"删除即删净"
- `SKILL.md` —— 增补同一条，约束被治理项目的文档维护
- `docs/{en,zh-CN,zh-TW}/plans/removal-hygiene.md` —— 本计划（三语）

### 风险

- 判定标准可能误伤：正常文本偶然出现被删内容的词，命中时人工区分"残留注脚"与"独立正常用法"。

### 验证方法

- 实例回查：本次 diff 案例，正文命中数为零。
- 规范落地：AGENTS.md 与 SKILL.md 各存在该条目。
- 门禁：文档对等与一致性检查通过。
