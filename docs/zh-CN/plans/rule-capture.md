# Rule Capture（TASK 计划）

[English](../../en/plans/rule-capture.md) · [简体中文](rule-capture.md) · [繁體中文](../../zh-TW/plans/rule-capture.md)

### 任务目的

不让治理要求只活在对话上下文里。开发者在任务过程中提出的每条**持久性**要求，必须在任务宣称完成前落进规则文件（`AGENTS.md` / `docs/rules/**`）——这样换开发者、换电脑、换会话时，新 Agent 继承的是同一套约束，而不是又开始"想当然"地乱改。

### 当前问题

对话里提的要求当场生效（Agent 本轮会遵守），但从不写进治理体系。上下文一结束就蒸发：

- 本次会话产生 5 条明确要求：只有 3 条完整落地，1 条只写进了被治理项目模板、**本仓库自己的 AGENTS.md 没写**，还有 1 条（"优先完善现有机制而非新增"）**任何文件里都没有**。
- 六阶段生命周期同步的是 代码 → 文档（CHANGELOG / Feature Registry / 架构），**没有任何一条义务覆盖"口头要求 → 规则文件"**。
- 结果：治理看起来实现了（Agent 整场表现正确），但仓库里根本没有——下一个 Agent 一无所知。

第二个更隐蔽的问题：Agent 无法可靠区分**持久规则**与**一次性指令**。全自动写入会用一次性决定污染规则库（例如"这次单次提交"只绑定那一堆混合改动）；反过来让开发者自己列"哪些该留"，等于把梳理工作推回去，还容易被一句"随便吧"敷衍掉。

### 提议方案

**AI 预分类、开发者裁定、一次任务一轮确认、未确认者留痕。**

1. **任务中收集** —— Agent 记录开发者提出的每一条要求。
2. **Phase 6 预分类** —— 报告给出规则沉淀清单，每条带**结论**而不是提问：
   - `[持久]` + 建议写入的文件/章节
   - `[一次性]` + 为何绑定本次任务
   - `[模糊]` + 明确请开发者裁定
3. **开发者裁定** —— 一句话确认或改判。
4. **写入** —— 确认为持久的规则走治理文件保护流程写入 `AGENTS.md` / `docs/rules/**`（原因 → CHANGELOG → 跑校验器；受保护文件完整清单见 `references/policies/governance-files.policy.md`，单一事实源，本页不复述）。写入绝不静默、绝不免确认：规则文件是受保护工件，Agent 无监督地给自己写约束，正是"Agent 不得自我解除限制"要禁止的反面。
5. **留痕** —— 未确认/未裁定的候选写入 `.governance/activity.jsonl` 的 `rules_pending` 字段，保证不静默消失，drift-check 能报"有 N 条候选规则未沉淀"。

**分类判据（写入规则正文）：**

| 信号 | 判为 |
| --- | --- |
| 祈使句 + 通用行为（"以后都""任何时候""不要再"）；约束行为模式；已重复出现 | 持久规则 |
| 绑定具体对象（"这个文件""这次"）；含范围限定词（"先""暂时""就这一次"）；执行完即失效 | 一次性指令 |
| 判断不了 | 模糊 —— 开发者裁定 |

**为何不做全自动**：规则文件受治理保护；涉及权限/安全/校验的改动必须用户明确确认。而且代价不对称——漏记一条规则的成本是重说一句话，错记一条是**永久的错误约束**，事后没人会回头审。

### 受影响文件

- `references/policies/lifecycle.policy.md` —— Phase 5 增加**规则捕获**同步项；Phase 6 报告增加**规则沉淀清单**小节
- `references/templates/agents-md.template.md` —— Phase 5 摘要加规则捕获；Documentation Map 分类补"开发者新提的普适要求 → `docs/rules/**`"
- `references/templates/sub-skills.md` —— state-manager 写入 `rules_captured` / `rules_pending` 到 `.governance/activity.jsonl`；drift-check `activity-report` 模式暴露待沉淀候选
- `AGENTS.md` —— 本仓库自身的同等义务（并补齐本次会话漏掉的两条规则）
- `CHANGELOG.md` —— Added 条目

### 风险

- **报告膨胀** —— 每个任务末尾都挂规则清单，对小改动是噪音；缓解：小型任务仅在存在候选时列出，否则一行"无新规则"
- **误分类** —— Agent 把一次性判成持久；缓解：写入前必经开发者裁定，且判据表把模糊情况偏向 `模糊` 而非 `持久`
- **受保护文件摩擦** —— 每条捕获规则都触发治理文件保护流程（CHANGELOG + 校验器）；缓解：同一任务的所有捕获规则合并为一次受保护文件改动
- **候选堆积** —— 开发者一直拖延会让 `rules_pending` 无限增长；缓解：drift-check 报告数量，把债务显性化

### 验证方法

- 构造含一条持久 + 一条一次性要求的任务 → Phase 6 报告两条判定正确（狗粮验证，人工）
- 确认后的规则出现在目标规则文件 + CHANGELOG 有条目（文档断言）
- 未确认的候选出现在 `.governance/activity.jsonl` 的 `rules_pending`（测试）
- drift-check `activity-report` 模式报出待沉淀候选数（测试）
- 本次会话漏掉的两条规则回填进本仓库 AGENTS.md（文档断言）
