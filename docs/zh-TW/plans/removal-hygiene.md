# 刪除即刪淨（TASK 計劃）

[English](../../en/plans/removal-hygiene.md) · [简体中文](../../zh-CN/plans/removal-hygiene.md) · [繁體中文](removal-hygiene.md)

> **狀態：設計計劃，未實作。** 交付對帳（`scripts/check-plan-delivery.js`）跳過純設計計劃；本行即標記。

**Target：both** —— 本倉庫側 `AGENTS.md`；載荷側 `SKILL.md`。同一規範兩處落地，清單見「受影響檔案」。

### 任務目的

確立文件變更規範——刪除或替換內容時，正文只保留改後的正確表述；刪除的原因記入歷史記錄層（CHANGELOG 或 ADR）。當前規範層（規則與文件正文）只陳述應做之事。

### 當前問題

- 刪除某內容後，正文又追加否定式注腳（「不再展示」「已刪除」「我們不這麼做」），把刪除動作本身寫進了當前規範。
- 本次會話實例：diff 已從確認流程移除，計劃正文卻寫「完整 diff 不預設展示」，經指出後清除。
- 注腳的危害：重新提及本不該出現的詞；誤導後續 Agent 以為該內容仍與流程相關；否定式禁令點出被刪內容的名字，反而引好奇。

### 提議方案

- 正文只寫應做之事：刪除一個概念，正文不出現它的名稱，也不出現「這裡曾有過別的」的任何痕跡。
- 正文自足：改後的文本讓未見過舊版的人讀不出刪除的痕跡。
- 歷史歸位：刪除的原因記入 CHANGELOG 或 ADR。
- 判定標準：用被刪內容的名稱全倉搜尋，正文命中數應為零；命中即未刪淨。

### 受影響檔案

- `AGENTS.md` —— Conventions 增加一條「刪除即刪淨」
- `SKILL.md` —— 增補同一條，約束被治理專案的文件維護
- `docs/{en,zh-CN,zh-TW}/plans/removal-hygiene.md` —— 本計劃（三語）

### 風險

- 判定標準可能誤傷：正常文本偶然出現被刪內容的詞，命中時人工區分「殘留注腳」與「獨立正常用法」。

### 驗證方法

- 實例回查：本次 diff 案例，正文命中數為零。
- 規範落地：AGENTS.md 與 SKILL.md 各存在該條目。
- 閘門：文件對等與一致性檢查通過。
